# OFF-AIR 운영 점검

## 배포 전

- npm run check: 형식·타입 검사와 API 회귀 테스트. 테스트는 가짜 저장소를 사용하며 운영 데이터를 변경하지 않습니다.
- npm run build: 공개/관리자 서버 빌드.
- npm run build:pages: GitHub Pages 빌드.
- main에 반영하면 GitHub Actions가 공개 화면과 두 Worker를 배포합니다. 두 작업 모두 성공해야 배포 완료입니다.

## 배포 후 확인

- 첫 방문 20개씩 표시, 검색·필터·페이지 이동·상세창 닫기/다시 열기.
- 모바일 가로 넘침, 키보드 이동, 갤러리 원본 보기.
- 사람 확인 실패 시 검토 대기로 접수. 인증되지 않은 글은 AI 호출 없이 관리자 검토로 보냅니다.
- 작성자 기기의 ‘내가 남긴 글’에서 대기/비공개 글도 삭제 가능. 브라우저 저장소를 지우면 삭제 권한도 사라집니다.
- 비공개·삭제된 기록의 이미지 주소는 공개 서버에서 404. 관리자 서버에서는 인증 후 확인 가능합니다.
- 이미 외부에 저장·다운로드된 이미지는 회수할 수 없습니다. 이전 버전에서 장기 캐시된 이미지도 캐시 만료 전 남아 있을 수 있습니다.

## 백업과 복구

GitHub는 코드 이력만 보관합니다. D1 데이터, R2 이미지와 서버 비밀 키는 별도입니다.

1. 큰 데이터 수정 전 Cloudflare D1의 내보내기로 전체 SQL을 보관합니다. CLI 사용 시 저장 경로를 명시하여 실행합니다:

   npx wrangler d1 export yeojeonhi-vtuber-archive-db --remote --config wrangler.personal.jsonc --output [비공개 백업 폴더]/archive.sql

2. R2의 yeojeonhi-profile-images 버킷은 별도 백업이 필요합니다. S3 호환 도구로 전체 객체와 키 경로를 보존하여 비공개 저장소에 복사합니다. 공개 GitHub에 올리지 않습니다.
3. 날짜별로 SQL·이미지·당시 Git 커밋을 함께 기록합니다. 제보 연락처와 비공개 댓글을 포함하므로 접근을 제한합니다.
4. 복구는 먼저 새로운 테스트 D1/R2에 진행합니다. SQL 가져오기 후 이미지 키 경로를 동일하게 복원하고, 기록·댓글 수와 이미지 표시를 대조합니다.
5. 검증 완료 후에만 운영 연결을 변경합니다. 운영 DB 위에 검증 없이 SQL을 실행하거나 객체를 덮어쓰지 않습니다.

이 문서는 절차이며 정기 자동 백업이 활성화된 것은 아닙니다. 자동 이미지 백업은 별도의 비공개 저장 위치와 자격 증명 설정 후 구성해야 합니다.
